# Día 2 · Bloque 3 — Construir y consultar el índice

Este bloque define una construcción local desde catálogo/corpus y dos comandos CLI, sin endpoint ni cambio de chat. El contrato completo es `index-contract.md` del material del curso; esta tarjeta fija subincrementos, evidencia y límites. El índice no se entrega: **este bundle no contiene índice generado**.

## Antes de empezar

Completa B2, valida catálogo v6 y corpus y registra tus aportes. Para una comprobación real necesitarás una clave de prueba Cohere personal, pero el ejercicio determinista usa un proveedor fake. No instales ni llames al proveedor sin autorización separada; esta tarjeta no autoriza cuentas, llamadas, despliegue ni commits. Nunca pongas la clave en frontend, argumentos, pruebas, logs o chat; backend únicamente mediante `COHERE_API_KEY`. Las llamadas consumen cuota y no hay reintentos.

## Subincrementos sugeridos

1. **B3-a · Validación/fragmentación.** Reutiliza `place-validation.ts` del kit. Un fragmento por lugar `### nombre exacto`; no indexar introducciones. Preservar texto y procedencia, ignorar encabezados dentro de fences; detener ante catálogo/corpus inconsistentes antes de cuota.
2. **B3-b · Formato y CLI fake.** Implementa ayuda y `index:build`/`index:query`; define esquema de índice v1 y solicitudes a proveedor reemplazable. Comprueba orden y forma con vectores deterministas simulados.
3. **B3-c · Errores y escritura atómica.** Lotes secuenciales de hasta 32; valida vectores; solo reemplaza índice tras construir/validar todo. Todo fallo conserva anterior; sin anterior no deja parcial.
4. **B3-d · Consulta/estado obsoleto.** Valida entrada, esquema y hashes antes de llamar. Consulta coseno, orden descendente y empate por `placeId`; máximo 3. Solo lectura, no reconstruye.
5. **B3-e · Evaluación semántica real separada.** Solo con autorización explícita de cuenta y llamadas; fija preguntas, conjunto relevante/objetivo antes de ver resultados. Un fallo top-3 se registra, no se manipula la pregunta.

## Interfaz de terminal y forma esperada

Desde `api/`, comandos esperados según contrato:

```sh
npm run index:build -- --catalog ./data/places.json --corpus ./data/corpus/lugares-valladolid.md --output ./data/places-index.json
npm run index:query -- --catalog ./data/places.json --corpus ./data/corpus/lugares-valladolid.md --index ./data/places-index.json --text "¿Dónde puedo probar cocina yucateca?"
```

Cada comando acepta `--help` como único argumento, salida 0 sin leer entradas ni consumir cuota. Rutas son explícitas y relativas al cwd. Construcción produce un JSON de una línea solo al terminar: `status:"built"`, chunks, modelo, dimensión, bytes y duración. Consulta produce `status:"queried"`, modelo, dimensión y hasta 3 `{placeId,name,score,text,source}`. Errores: stdout vacío, mensaje contractual en stderr, código según `index-contract.md` §8. No imprimir consulta, cuerpos de proveedor, stack ni secreto.

Índice v1: Cohere `embed-v5.0-pro`, 1024 dimensiones, `search_document` build / `search_query` query; un vector no nulo finito por lugar. Guarda hashes SHA-256 exactos de catálogo/corpus, texto completo y procedencia (nombre de archivo, encabezado, rango inclusivo; nunca ruta absoluta). No incluye credenciales, historial ni índice precalculado. Consulta rechaza cambios con `stale_index` antes del proveedor; build no trunca textos ni reconstruye incrementalmente.

**Ejemplos de aceptación**

- Catálogo inválido/fragmento faltante: `invalid_data`, cero llamadas, archivos intactos.
- Cambio de espacio en corpus: consulta devuelve `stale_index`, cero llamadas, sin escritura.
- Vector de dimensión equivocada, cero, no finito o faltante: fallo sin reemplazar archivo anterior.
- Tres vectores controlados producen coseno calculado sin asumir normalización; empates por ID ascendente; salida no más de tres con fuente intacta.
- Pregunta de recomendación predefinida: top-3 pertenece al conjunto relevante previamente fijado. Pregunta sobre atributo distintivo del aporte: `placeId` esperado en top-3. Estos dos son checks semánticos reales separados de pruebas fake; si no pasan, registra el hallazgo, no afirmes calidad general.
